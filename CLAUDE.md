## Project Overview

Simple Mouse Gestures is a Google Chrome extension (Manifest V3) written in TypeScript and built with
[WXT](https://wxt.dev). Users draw gestures with the right mouse button held down; each gesture sequence
(up/right/down/left) maps to a browser action (go back, close tab, etc.). Works on Windows, Linux, and macOS.

## Development

- Install: `npm ci` (Node.js 24+). `wxt prepare` runs on postinstall and generates `.wxt/` (types, base tsconfig).
- Run: `npm run dev` starts WXT dev mode (auto-reload). Or `npm run build` and load `.output/chrome-mv3` as an unpacked
  extension via `chrome://extensions`.
- Type check: `npm run typecheck`. Test: `npm test` (Vitest, config in `vitest.config.ts`, tests in `tests/` mirroring
  `src/`). Format: `npm run format` / `npm run format:check` (Prettier, `.prettierrc`: 120 print width, single quotes,
  CRLF).
- The manifest is generated by WXT: shared fields (name, permissions, icons, `version_name`) live in `wxt.config.ts`,
  entrypoint-specific options (matches, `run_at`, `all_frames`) live in the entrypoint files, and `version` comes from
  `package.json`. There is no `manifest.json` in the repo.
- `wxt.config.ts` sets `CHOKIDAR_USEPOLLING=1` because native file watching fails on network-drive checkouts; do not
  remove it.
- Release: bump `version` in `package.json` and `version_name` in `wxt.config.ts`; merge the version branch (`v0.9.0`)
  to `master`. CI uploads the store-ready zip as a workflow artifact (`npm run zip` builds it locally into `.output/`).

This project uses OpenSpec for spec-driven changes (`openspec/` directory, `opsx:*` slash commands).

## Architecture

All source lives in `src/`. WXT entrypoints (`src/entrypoints/`) are thin composition roots; the classes they wire live
in plain TS modules. Three isolated Chrome extension contexts communicate via `chrome.runtime` messages and
`chrome.storage.local` (typed in `src/shared/types.ts`):

### Content script (`src/entrypoints/content.ts` + `src/content-scripts/`)

One bundled entrypoint (`defineContentScript`: all URLs, all frames, `document_start`). Adding a content-script class
means adding a module and importing it — no manifest bookkeeping.

Flow: `ContentEventHandler` listens for right-button mousedown/mouseup. On mousedown, `SelectedTextHandler` snapshots
the current selection, `LinkHandler` snapshots the nearest http(s) link under the cursor, and `GesturesHandler` starts
recording mouse movement, converting movement angles into a sequence of `up`/`right`/`down`/`left` tokens (deduplicating
consecutive repeats). While recording, a full-screen canvas overlay
(`CanvasBuilder`/`CanvasHandler`/`CanvasEventHandler`) draws the gesture trail using line settings read via
`SettingsStorage`. On mouseup with a non-empty gesture, it sends a `gestures` message (gestures, selected text, link
URL) to the service worker and suppresses the next context menu.

Context menu handling is platform-dependent (`PlatformDetector`): on Linux/macOS the native menu opens on right-button
press, which would interrupt gestures, so `ContentEventHandler` suppresses it by default — a gesture-free right click
arms a 500 ms window during which a second right click opens the native menu. On Windows the menu opens on release, so
only the context menu following a completed gesture is suppressed.

### Service worker (`src/entrypoints/background.ts` + `src/service-worker-scripts/`)

`defineBackground` with `type: 'module'`. Handles two message types: `gestures` (execute the matched operation) and
`updateStorage` (re-read storage after the popup saves changes).

`OperationResolver` serializes the gesture array to a pipe-joined key (`up|left`), looks it up in the stored
gesture→operation map, and calls the matching operation's `doAsync(context)`. `Context` carries the gestures, any
selected text, and the link URL captured under the cursor at gesture start.

To add a new operation: create a class in `src/service-worker-scripts/operations/` implementing the `Operation`
interface (async `doAsync(context)`; catch and log errors from Chrome APIs, as the existing operations do), then import
and register it in the `OperationResolver.operations` static map with a unique key and display label. The popup's
operation dropdown is populated from that map automatically. Update the action list in `README.md`.

### Popup (`src/entrypoints/popup/`)

`index.html` + `main.ts` plus the popup classes, all co-located in the entrypoint directory. The UI has three tabs:
Gestures (gesture→operation mappings, validated inline instead of via `alert()`), Settings (line color/width, auto-saved
on change — there is no Save button), and Backup (export/import of all settings as a versioned JSON file;
`BackupHandler` validates imported gestures, operation keys, and settings, then `Storage.replaceAllAsync` replaces
everything after a modal confirmation). It imports `OperationResolver` from `service-worker-scripts/` directly to
enumerate available operations. `GesturesSerializer` converts between the UI letter form (`UL`) and the storage form
(`up|left`). After every save, the popup `Storage` sends `updateStorage` so the service worker reloads its cached state.

Styling mimics Chrome's design language through CSS custom properties (design tokens) defined in `style.css`. The color
picker is the `@melloware/coloris` npm package (`Coloris.init()` binds inputs with the `data-coloris` attribute), themed
by overriding its public CSS classes from `style.css`.

### Shared state and conventions

- `chrome.storage.local` holds JSON-stringified values under two keys defined once in `src/shared/storage-keys.ts`
  (gesture→operation map and `lineColor`/`lineWidth` settings). Defaults are seeded by
  `src/service-worker-scripts/storage.ts` on first run.
- There are three separate storage classes — `src/service-worker-scripts/storage.ts` (caches in memory, seeds defaults),
  `src/entrypoints/popup/storage.ts` (read/write, notifies service worker), and
  `src/content-scripts/settings-storage.ts` (read-only settings). They stay separate on purpose; only the keys are
  shared.
- `src/shared/consts.ts` (`Consts` as const object) defines mouse button codes, gesture direction names, and message
  types; `src/shared/types.ts` holds the domain types (`Direction`, the message union, `Settings`, `GestureMap`,
  `BackupData`). `Settings.lineWidth` is `number | string` because the settings tab has historically stored select
  values as strings.
- Code style: strict TypeScript, classes with `#private` fields and methods, constructor dependency injection, early
  returns, explicit imports (WXT auto-imports are disabled), no comments.
