# Proposal: migrate-to-typescript-wxt

## Why

The extension is ~1,650 lines of vanilla JavaScript with no build system, no type checking, and no tests — every change
is verified by hand in the browser, and refactoring is risky. The content scripts additionally depend on a fragile
manual load-order list in `manifest.json`. Migrating to TypeScript with the WXT extension framework brings type safety
(including typed Chrome APIs), real ES modules everywhere, automated tests for the core logic, and a CI pipeline that
produces a store-ready zip on every master build.

## What Changes

- Adopt WXT as the build system and development toolchain (npm project, `wxt dev`, `wxt build`, `wxt zip`).
- Convert all source files from vanilla JavaScript to TypeScript under WXT's project layout; classes keep their current
  structure (constructor DI, `#private` fields, early returns).
- **BREAKING** (dev workflow only): the extension is no longer loadable from the repo root; developers load the WXT
  build output directory instead. Runtime behavior in the browser is unchanged.
- The manifest is generated by WXT from config and entrypoints; the hand-maintained 12-file content-script load-order
  list disappears — content scripts become a single bundled entrypoint with real imports.
- Replace the vendored Coloris color picker in `popup/dependencies/` with the npm package it came from.
- Add Vitest unit tests for the pure logic: gesture tokenization, gesture serialization, operation resolution, and
  backup validation. Chrome-API-dependent layers are out of scope for now.
- Add a GitHub Actions workflow: type-check, Prettier check, tests, and build on every push and pull request; on pushes
  to `master` additionally produce the Chrome Web Store zip and upload it as a CI artifact.
- Stop committing release zips (`SimpleMouseGestures<version>.zip`) to the repo root; CI artifacts replace them.
- Update `README.md` and `CLAUDE.md` for the new development workflow.

## Capabilities

### New Capabilities

- `typescript-build`: WXT-based TypeScript build system — project layout, entrypoints, manifest generation, dev mode,
  and production build output equivalent to the current extension.
- `unit-tests`: Vitest test suite covering the pure logic (gesture tokenization, gesture serialization, operation
  resolution, backup validation) with a repeatable `npm test` run.
- `ci-pipeline`: GitHub Actions workflow that validates every push/PR (type-check, format check, tests, build) and
  uploads a store-ready zip artifact on `master` builds.

## Impact

- **All source files**: every `.js` file under the repo root, `content-scripts/`, `service-worker-scripts/`, and
  `popup/` is converted to `.ts` and relocated into the WXT project layout; `manifest.json` is replaced by WXT config.
- **New dependencies**: `wxt`, `typescript`, `vitest`, `@types/chrome` (via WXT), Coloris as an npm package; a
  `package.json` and lockfile are introduced.
- **Repo layout**: new `package.json`, `wxt.config.ts`, `tsconfig.json`, `src/` (or WXT `entrypoints/`) tree, test
  files, `.github/workflows/`; `dist`/`.output` and `node_modules` are git-ignored; vendored `popup/dependencies/` and
  committed release zips are removed.
- **Developer workflow**: `npm install` + `wxt dev`/`wxt build` replace "load the repo root as unpacked"; Prettier
  config gains TypeScript coverage; `.prettierignore` no longer needs the vendored-dependency exclusion.
- **Docs**: `README.md` (development/release sections) and `CLAUDE.md` (build, layout, conventions) need rewriting.
- **Release process**: zips come from CI artifacts instead of being built locally and committed.
